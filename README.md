# AutoTech Plus: website prototype

Static site. Open `index.html` directly in Chrome/Edge, or run `npm run dev` and visit http://localhost:8080.

- `index.html`, `css/styles.css`, `js/main.js`: the page
- `js/hero-video.js`: hero background video carousel (synced to the service tabs)
- `assets/video/`: hero clips (trimmed and colour-graded, 720p H.264) with poster frames

Hero footage is royalty-free stock from Mixkit (free for commercial use, no attribution required):
servicing = mixkit #13270, wheels = #17132, MOT = #17133, ECU = #2675; About photo = still from #4716.
Swap in real footage from the workshop when available: same filenames, around 7 s, 1280x720 or larger.

`src/hero3d.js` is an unused real-time 3D hero from an earlier iteration (`npm run build:3d`).

## MOT booking

Every "Book MOT" button (and any link to `#book`) opens the booking dialog in `js/booking.js`:
service → date & time → details → confirmation (with an .ics "add to calendar" download).
Opening hours, slot length, lead time and services are in `CONFIG` at the top of that file.

It currently runs on **sample availability** (a made-up but realistic diary) so it can be demoed.
To connect the garage's live calendar, set `window.AUTOTECH_BOOKING_API` and provide a small backend:

    GET  /availability?from=ISO&to=ISO  -> { "busy": [ { "start": ISO, "end": ISO } ] }
    POST /bookings  { service, serviceName, start, end, reg, name, phone, email, waiting, notes }
                                         -> { "reference": "ATP-1234" }   (409 if the slot was just taken)

These map onto Google Calendar (freebusy + events.insert), Microsoft 365 (getSchedule + create event),
or a garage management system's API. The backend must re-check the slot before creating the booking.

## Pages

- `index.html`: home
- `services.html`: all 8 services (MOT, servicing, diagnostics, gearbox, brakes & clutch, remapping, suspension & steering, air-con)
- `faq.html`: searchable FAQ with topic filters (and FAQ schema for Google)
- `contact.html`: contact cards with a live "open now" badge, message form (`?service=gearbox` pre-selects the service), map

The header, footer, services, FAQ and contact pages are generated by `python3 tools/gen_pages.py`.
Edit the text in that script and re-run it; it also syncs the header and footer into `index.html`.
Note: the contact and call-back forms are front-end only for now. They need a form backend (e.g. Formspree, or the same API as bookings) to actually send.

## Bristol Gearbox (bristolgearbox.co.uk)

The gearbox specialist site is built into `bristolgearbox/` by `tools/gen_gearbox.py` (run `python3 tools/gen_pages.py`, which builds both sites).
It uses the same design, CSS and JS, and the main site links to it as **Gearbox** in the nav, the footer, the gearbox service tile and the services page.

- It keeps the URLs Google already ranks: `/`, `/about/`, `/offer/`, `/book-now/`, `/powershift/`, `/dsg/`, `/cvt/`, `/semi-auto/`, `/blog/`, `/powershift-dsg-repair-bristol/`.
- `bristolgearbox/` is self-contained (the build copies the CSS, JS and images into it), so deploy that folder as the root of bristolgearbox.co.uk.
- Every page has a canonical URL on bristolgearbox.co.uk, plus LocalBusiness/breadcrumb (and FAQ where relevant) schema, `sitemap.xml` and `robots.txt`.
- `bristolgearbox/_redirects` 301s the retired WordPress URLs (`/pass-plus/`, `/locations/`, `/sample-page/` ...). The root `_redirects` sends `autotechplus.co.uk/bristolgearbox/*` to the gearbox domain so the pages only live in one place.
  Both files use Netlify / Cloudflare Pages syntax.
- Links back to the main site use `MAIN` in `gen_gearbox.py` (currently `https://autotechplus.co.uk/`).
- Preview locally: `cd bristolgearbox && python3 -m http.server 8081`, then http://localhost:8081/.

Forms: every enquiry form (`form[data-lead]`) posts to `window.AUTOTECH_FORM_ENDPOINT` when it is set (e.g. a Formspree URL); otherwise it only shows the thank-you message.
